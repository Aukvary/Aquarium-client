# Aquarium-client

Интерактивный терминальный клиент для трекера задач Aquarium, разработанный на C++ с использованием библиотеки **FTXUI** и протокола **gRPC**.

---

## Возможности

- **Доска задач (`Tasks`)**: трёхколоночный интерфейс со списком задач, фильтрацией по статусам (`ALL`, `PLAN`, `ACTIVE`, `IN_REVIEW`, `COMPLETE`, `VERIFIED`, `ARCHIVE`), поиском, деталями задачи и лентой комментариев.
- **Ревью задач (`Review`)**: рабочая область для проверки задач в статусе `IN_REVIEW` с возможностью одобрения (`Approve & Verify` -> `VERIFIED`) или возврата на доработку с обязательным указанием причины (`Reject with Reason` -> `ACTIVE`).
- **Создание задач (`Create Task`)**: форма создания задачи с заголовком, описанием, начальным статусом (`PLAN` / `ACTIVE`), списком исполнителей, проверяющим и сроком выполнения (`YYYY-MM-DD`).
- **Обновления в реальном времени**: фоновая подписка на gRPC-поток `SubscribeEvents` с автоматическим переподключением и всплывающими уведомлениями (toast).
- **Мониторинг соединения**: периодическая проверка `UtilsService/Health` с отображением статуса в нижней строке состояния (`[HEALTH: OK]`, `[CONNECTING...]`, `[RECONNECTING...]`, `[OFFLINE]`).
- **Управление сессиями**: сохранение токенов по серверам в локальном конфиге и окно регистрации по инвайт-ключу (`AuthModal`).
- **Клавиатура и мышь**: поддержка vim-подобной навигации (`j`/`k`, `/`, `f`, `1`–`3`, `q`) и кликов/прокрутки мышью.

## Зависимости и структура рабочего пространства

### Системные требования

- Компилятор с поддержкой **C++20** (GCC / Clang / MSVC)
- **CMake** `>= 3.20`
- **Ninja** (рекомендуется)
- **Protobuf** и **gRPC** (`protobuf`, `grpc++`, `protoc`, `grpc_cpp_plugin`)
- Опционально (подтягиваются автоматически через `FetchContent`, если не установлены в системе):
  - **FTXUI** (`v5.0.0`)
  - **nlohmann_json** (`v3.11.3`)
  - **GoogleTest** (`v1.14.0`)

### Расположение репозиториев

При сборке клиент генерирует C++ и gRPC исходники напрямую из `.proto`-файлов сервера (`../Aquarium-server/proto`), поэтому репозитории должны располагаться рядом в одной директории:

```text
Aquarium/
├── Aquarium-client/
└── Aquarium-server/
    └── proto/
        ├── TaskStoreService.proto
        ├── UserStoreService.proto
        └── UtilsService.proto
```

## Сборка и тестирование

### 1. Клонирование

```bash
git clone https://github.com/Aukvary/Aquarium-server.git
git clone https://github.com/Aukvary/Aquarium-client.git
cd Aquarium-client
```

### 2. Конфигурация и сборка

```bash
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

После сборки будут доступны бинарные файлы:
- `build/aquarium-client` — основной TUI-клиент
- `build/aquarium-client-unittest` — модульные тесты

### 3. Запуск тестов

```bash
ctest --test-dir build --output-on-failure
```

Быстрая проверка запуска (smoke-test):

```bash
./build/aquarium-client --smoke-test
```

## Запуск и параметры командной строки

```bash
./build/aquarium-client [options]
```

| Флаг | Описание |
|---|---|
| `-s, --server <host:port>` | Адрес целевого gRPC-сервера (переопределяет конфиг) |
| `-t, --token <token>` | Bearer-токен аутентификации (переопределяет конфиг) |
| `--smoke-test` | Выполнить smoke-test и завершить работу |
| `-h, --help` | Показать справку по флагам |

### Переменные окружения

Если флаги командной строки не заданы, клиент проверяет переменные окружения:
- `AQUARIUM_SERVER` — адрес сервера (`host:port`)
- `AQUARIUM_TOKEN` — токен аутентификации
- `XDG_CONFIG_HOME` — базовая директория для хранения конфигурации

> [!TIP]
> Сервер `Aquarium-server` в конфигурации Docker Compose по умолчанию слушает gRPC на порту `8081` (в то время как клиент по умолчанию использует `localhost:50051`). Для подключения к локальному серверу из Docker укажите порт явно:
> ```bash
> ./build/aquarium-client -s localhost:8081
> ```

## Конфигурация и первый вход

Файл конфигурации создаётся автоматически по пути:
- `$XDG_CONFIG_HOME/aquarium/config.json`, либо
- `~/.config/aquarium/config.json`

Пример структуры (см. [client-config.default.json](configs/client-config.default.json)):

```json
{
    "active_server": "localhost:50051",
    "servers": {
        "localhost:8081": {
            "user_id": 1,
            "user_name": "developer",
            "auth_token": "bearer_token_string"
        }
    }
}
```

Если для активного сервера нет сохранённого токена, при запуске откроется модальное окно **REGISTRATION / LOGIN**, в котором нужно указать адрес сервера, имя пользователя и секретный `Invite Key` (см. `INVITE_KEY` на сервере). После успешного вызова `UserStoreService/AddUser` полученный токен автоматически сохраняется в `config.json`.

## Управление (горячие клавиши)

> [!NOTE]
> Минимальный размер терминала для корректного отображения интерфейса — **80×24**.

### Глобальные

| Клавиша | Действие |
|---|---|
| `1` / `2` / `3` | Переключение вкладок: **Tasks** / **Review** / **Create Task** |
| `Tab` / `Shift+Tab` | Перемещение фокуса между элементами и панелями |
| `Esc` | Закрыть модальное окно / скрыть toast-уведомление / выйти из поиска |
| `q` / `Ctrl+C` | Выход из приложения (`q` срабатывает, когда фокус не в поле ввода) |

### Вкладки `Tasks` и `Review`

| Клавиша | Действие |
|---|---|
| `j` / `↓` | Выбрать следующую задачу в списке и загрузить комментарии |
| `k` / `↑` | Выбрать предыдущую задачу в списке и загрузить комментарии |
| `/` | Перевести фокус в строку поиска (на вкладке `Tasks`) |
| `f` | Циклическое переключение фильтра статусов (на вкладке `Tasks`) |
| `Enter` | Отправить комментарий (когда фокус в поле замечаний) или подтвердить форму |
| **Мышь** | Выбор вкладок, фильтров, задач, кнопок действий и прокрутка списков |
